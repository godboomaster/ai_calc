# Эксперимент: Koog в генерации интерфейса

Следующий этап проверки: [фон, восстановление и Android API 26](RECOVERY.md).
Также проверены [ошибки совместимости](COMPATIBILITY.md) и
[провайдеры и реальные изображения](PROVIDERS-AND-PHOTOS.md).

Ветка `codex/koog-compatibility`, только изолированная debug-сборка:

```powershell
./gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug -PisolatedDeviceCheck -PkoogProbe --max-workers=2
```

`GenerationController` и проверка соединения в `SolutionViewModel` получают
`CompletionTransport` из варианта сборки. При `koogProbe` это Koog DeepSeek,
без флага и в release — прежний HTTP-клиент. Основная установка не обновляется.
Произвольные провайдеры в эксперименте отклоняются понятной ошибкой; скрытого
возврата на старый клиент нет. Разрешены официальный DeepSeek и loopback для тестов.

Адаптер переводит сообщения в публичный Prompt API Koog, передаёт текущую модель,
thinking, JSON mode и исходные схемы инструментов с ограничениями. Возвращает
текст, reasoning и tool calls в существующий ограниченный LibraryAgentLoop.
Хранение запросов, фоновые сервисы, лимиты POST, примеры и история остаются прежними.
Распознавание импортируемых документов пока использует прежний транспорт.

Особенности:
- Нет нового сервера или посредника; запрос идёт из приложения в настроенный API.
- Ключ получает только приложение из существующих настроек, без копирования в код/логи.
- SDK-ошибки заменяются локальным сообщением со статусом HTTP, без исходного cause.
- Отмена coroutine сохраняется. Redirect, retry и автоматический повтор POST отключены.
- Клиент закрывается после каждого completion; межзапросный пул пока не оптимизирован.
- Фото передаются как JPEG base64 через публичный API. При выключенной поддержке
  изображений запрос отклоняется с пояснением до сети. Реальное чтение фото DeepSeek
  проверено отдельно; тест сериализации сам по себе этого не доказывает.
- Отсутствующий или `null` `system_fingerprint` заменяется пустой строкой только
  для DTO Koog. Приложение не использует это служебное поле; остальные обязательные
  поля ответа не подставляются. См. [проверку совместимости](COMPATIBILITY.md).
- SDK разбирает JSON аргументов инструментов раньше LibraryTools. Для Koog 1.3
  добавлен per-completion `KoogResponseBridge`: только представление для SDK
  заменяет невалидные строки аргументов на `{}`, а цикл получает исходные вызовы.
  LibraryTools возвращает `invalid_arguments`, и модель может исправиться в пределах
  прежнего бюджета. При следующем POST отправляются исходные аргументы и reasoning.
  Мост не делает сетевых повторов, не чинит аргументы перед исполнением и не хранит
  исходный ответ на диске. Некорректная оболочка ответа по-прежнему отвергается SDK.
- Сетевые исключения SDK распознаются по цепочке причин и заменяются новыми
  исключениями нужного типа без исходного сообщения/cause: UI различает отсутствие
  соединения, тайм-аут и ошибку ответа. HTTP-статусы имеют приоритет.

## Визуальная проверка 2026-10-14

На SmartCalc_API35 установлен APK через `adb install -r`, существующие данные сохранены.
Через интерфейс с сохранёнными настройками DeepSeek отправлена синтетическая задача:
«Вычисли 17 × 23. Дай краткий ответ и один шаг решения». Ответ **391** появился
в истории и восстановился на дисплее. После отправки можно было ввести 7 в
калькулятор и свернуть приложение; по возвращении расчёт остался 7, ответ был в истории.
Приложение не принудительно останавливалось, завершение процесса ОС не проверялось.
Дополнение «Прибавь 9 к предыдущему ответу» вернуло **400** в той же цепочке.
API-ключ не читался, не извлекался и не копировался: его использовало приложение.
Реальные фотографии и поиск по пользовательским материалам провайдеру не отправлялись.

Компиляция release с экспериментальными флагами прошла, используя legacyTransport.
Итоговые проверки: 341 unit-тест (0 ошибок), assembleDebug/assembleDebugAndroidTest,
lintDebug — успешно; KoogGenerationTest на Android API 35 — OK (6 tests), 1.524 с.
Покрыты параметры и изображения в запросе, работа настоящего LibraryAgentLoop
с локальным каталогом, reasoning, ошибки, отмена, запрет redirect/повтора POST
и безопасный отказ при повреждённых аргументах инструмента.
Это результаты первого этапа подключения UI. Ограничение некорректных аргументов
исправлено следующим этапом ниже.

## Восстановление аргументов и проверка поиска

Регрессионный тест сначала воспроизвёл сбой, затем прошёл для повреждённого JSON,
массива, `null`, пустой строки и числа: `invalid_arguments` → исправленный поиск →
ответ. Проверены исходные аргументы, reasoning, лимит финального раунда, отсутствие
повторной отправки при обрыве соединения. Независимое ревью моста дефектов не выявило.

Ручная проверка на API 35: агент нашёл и прочитал синтетический пример
SYNTHDS20261013 (2 Ом, 6 В). Для новой задачи (4 Ом, 20 В) ответил 5 А; в просмотре
решения показан фактически прочитанный пример. Отмена активного дополнения дала
«Прервано» и «Вычисление отменено. Можно повторить запрос».

На недоступном локальном endpoint выявлено неверное сообщение об ошибке модели
при отказе соединения. Добавлен отдельный тест (наблюдался RED) и сохранение
безопасной сетевой классификации. Ключ ни для тестов, ни для диагностики не читался.

После исправления повторная проверка UI показала «Не удалось подключиться к серверу.
Проверьте base URL в настройках» и кнопку повтора. Рабочий адрес
`https://api.deepseek.com` восстановлен и сохранён; нажатие «Повторить запрос»
успешно завершило задачу 6 × 7 ответом **42**. Проверка проводилась в изолированном
`com.smartcalc.app.importcheck`, без удаления данных и изменения основного приложения.

Итог: 344 unit-теста без ошибок, assembleDebug/assembleDebugAndroidTest и lintDebug
успешны. На эмуляторе API 35 KoogGenerationTest: **OK (9 tests)**, 2.437 с.
Восстановление повреждённых аргументов проверено на синтетических ответах сервера;
реальный запрос подтвердил поиск и чтение примера, отмену и успешный повтор после
сетевой ошибки. Независимое ревью обработки сетевых исключений дефектов не выявило.
