# Koog: провайдеры и фото, 2026-10-14

Ветка `codex/koog-compatibility`, только изолированная debug-сборка. Пользовательский
API-ключ не читался, не копировался и не менялся. Для реального запроса ключ
использовало само приложение. Основная установка и release остаются на прежнем клиенте.

## Граница провайдеров

- DeepSeek: проверен реальный запрос с изображением через сохранённые настройки
  `https://api.deepseek.com`, модель `deepseek-flash`.
- Loopback: контрактные тесты подтвердили Base URL `/`, `/v1`, `/v1/`, правильный
  путь `/chat/completions`, сохранение имени модели и Authorization с фиктивным ключом.
- OpenAI, OpenRouter и произвольный gateway **ещё не поддерживаются этим адаптером**.
  Проверен явный отказ ApiConfigurationException до DNS/HTTP, без скрытого перехода
  на прежний клиент и без передачи ключа. Это не успешная интеграция с их API.
  Аналогично отклоняется похожий домен `api.deepseek.com.evil.test`.

Итак, проверка этого этапа не закрывает перенос всех провайдеров на Koog:
нужны отдельные адаптеры/маршрутизация и реальные проверки соответствующих API.
Внешние запросы к OpenAI/OpenRouter в этом этапе не выполнялись.

## Реальная проверка фото

Документация DeepSeek описывает vision для `deepseek-flash` и `image_url` в Chat
Completions: https://api-docs.deepseek.com/guides/vision/

Через системную галерею на API 35 отправлены синтетические изображения проекта.
На наклонённом листе `i06-tilted.jpg` модель распознала передаточную функцию
`4/(0.5s+1)` и вернула соответствующие частотные характеристики. Поскольку в
библиотеке уже есть такие примеры, отдельно проведён независимый контроль:

- Фото: [vision-k731.jpg](fixtures/vision-k731.jpg), создано только для этого теста.
- На картинке: `47 + 28`, `13 × 6` и код `VISION-K731`.
- Текстовое условие отдельно не вводилось; отправлено только изображение.
- Ответ на дисплее: `47 + 28 = 75; 13 × 6 = 78; код: VISION-K731`.
- SHA-256 изображения: `7f970dcbfff9d0dbb67b6134b338eda1781588257390702d733d29dbc112a57b`.

Это подтверждает фактическое чтение изображения моделью через Koog, а не только
наличие base64 в запросе. Оно не гарантирует распознавание любых размытых/рукописных
фото или математическую правильность сложных решений.

Локальный тест дополнительно проверяет порядок пяти изображений: условие образца,
решение образца, оформление, две страницы новой задачи. Текстовые метки сохраняются,
JPEG data URL не теряются и не переставляются.

## Найденная проблема

При выключенном «Модель поддерживает изображения» SDK уже отклонял фото до сети,
но транспорт превращал это в общую ошибку ответа модели. Пользователь не понимал,
что нужно изменить в настройках. Тест воспроизвёл этот отказ до исправления.

В KoogCompletionTransport добавлена ранняя проверка всех `image_url` в сообщениях:
при выключенной настройке возвращается понятная ApiConfigurationException
«Выберите модель с поддержкой фото и включите … Запрос не отправлен».
Это касается и фото задачи, и образцов, и ранее сохранённого контекста.
Проверка не угадывает возможности модели по имени: флаг должен соответствовать
реальной поддержке vision у выбранного API. Рабочие настройки пользователя не менялись.

Независимое ревью исправления дефектов не выявило.
