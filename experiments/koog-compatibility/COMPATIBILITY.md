# Koog: ошибки совместимости, 2026-10-14

Проверка только экспериментального транспорта (`-PisolatedDeviceCheck -PkoogProbe`).
Пользовательский API-ключ не читался; тесты используют локальный MockWebServer и
фиктивный `synthetic-key`. Для DNS используется подставной resolver, поэтому
никакого запроса к внешнему API или настоящему DNS нет.

## Найденная проблема и исправление

Корректный JSON-ответ без `system_fingerprint` приводил к ApiException из-за DTO
Koog. Новый тест воспроизвёл сбой до исправления (13 тестов, один failed).

`KoogResponseBridge` (бывший `KoogToolArgumentsBridge`) подставляет пустую строку
для отсутствующего/null fingerprint только в представление ответа для SDK.
Это не идентификатор сервера: приложение не сохраняет и не показывает поле.
Содержимое решения, reasoning и исходные tool calls не изменяются. Обязательные
поля ответа не выдумываются; повреждённый JSON и некорректная оболочка отвергаются.
Content-Length пересчитывается существующим механизмом моста.

## Проверенные сценарии

- Отсутствующий и null fingerprint: корректный ответ принимается с одного POST.
- Поиск и чтение примера с tool calls без fingerprint: три ожидаемых POST,
  исходные аргументы и reasoning сохранены в продолжении агентного цикла.
- Общий тайм-аут запроса и тайм-аут чтения сокета проверены раздельно, каждый
  при задержке заголовков и при задержке тела ответа. UI получает локальный текст
  про тайм-аут, дополнительных отправок нет.
- Ошибка DNS: один вызов resolver, ноль отправок; сообщение «Нет соединения
  с интернетом». Исходные сообщения исключений не попадают в ошибку приложения.
- Обрыв посреди тела ответа: частичный ответ не публикуется, один POST,
  безопасная сетевая ошибка без скрытого повтора.
- Повреждённые JSON/оболочка: безопасный отказ без дополнительного POST.

Для воспроизводимости у транспорта добавлены параметры конструктора `timeoutConfig`
и `dns`. По умолчанию остаются прежние 180/30/120 секунд и `Dns.SYSTEM`.
В тестах используется короткий тайм-аут; настройки пользователей не менялись.

Проверки находятся в `KoogGenerationTest`, общий набор запускается на JVM и Android.
В release и обычной debug-сборке Koog по-прежнему не включён.

## Результаты

- Полный JVM-набор: **353 теста, 0 ошибок**.
- `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug`: BUILD SUCCESSFUL.
- API 35: KoogGenerationTest + KoogRecoveryTest — **OK (18 tests)**, 6.140 с.
- API 26: тот же набор — **OK (18 tests)**, 6.193 с.

APK установлены через `install -r`, без очистки данных. Сетевые сценарии выполнялись
в автоматических тестах с проверкой текста, предназначенного для UI; реальные
ошибки внешнего провайдера намеренно не провоцировались.
