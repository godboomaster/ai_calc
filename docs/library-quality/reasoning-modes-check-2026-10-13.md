# Общие настройки рассуждения и содержательные шаги

Пользователь запросил OpenAI, Qwen, Kimi, GLM и DeepSeek. Прежнее ограничение
переключателя официальным DeepSeek заменено общим сохраняемым форматом API.
По умолчанию «Авто»; для совместимых шлюзов можно явно выбрать формат.
Неизвестная комбинация в авто сохраняет режим сервера без лишнего параметра.

| Формат | Передаваемый параметр | Источник контракта |
| --- | --- | --- |
| DeepSeek / Kimi / GLM | thinking.type enabled/disabled | [DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/), [Kimi](https://github.com/MoonshotAI/Kimi-K2.5), [GLM](https://docs.z.ai/guides/capabilities/thinking) |
| Qwen | enable_thinking true/false | [Alibaba](https://www.alibabacloud.com/help/en/model-studio/deep-thinking) |
| OpenAI | reasoning_effort high/none или минимальное допустимое значение | [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [модели рассуждения](https://developers.openai.com/api/docs/guides/reasoning) |
| Как задано на сервере | параметр режима не добавляется | явный выбор пользователя |

Распознавание официальных адресов и моделей консервативно: Qwen ограничен
qwen-plus/qwen-flash/qwen3.8-max, Kimi — kimi-k2.5; другие варианты можно настроить
вручную по контракту конкретной модели. API-формат и поддержка отключения зависят
от модели и шлюза. Qwen, требующие потоковую выдачу, текущим транспортом не поддержаны.
При постоянном thinking (старые GPT-5/o-серия, GPT-6, GLM-5.3) подпись переключателя
говорит о подробности: выключение задаёт minimal/low, без ложного обещания выключить.
Для GLM-5.3 thinking остаётся enabled и меняется reasoning_effort high/low.
Модели GPT-6, не поддерживающие tools в Chat Completions, останавливаются локально
до POST при включённом поиске. Responses API этим изменением не добавлен.

Все фактические POST решения, дополнения, проверки соединения и распознавания
проходят общий адаптер. В tool turns рассуждения возвращаются в исходном виде
при наличии, включая режим сервера, но не сохраняются и не отображаются.
DeepSeek требует поле явно; OpenAI/Qwen/GLM могут его не вернуть. Лимиты прежние.
Для GLM первый поиск использует auto даже без thinking, финальный запрос исключает
tools и tool_choice, поскольку документирован только auto; локальный запрет
продолжения tool calls и максимум 4 POST сохраняются.

## Состав решения

В эмуляторе исходный живой ответ подтвердил лишний шаг «Поиск похожего примера».
Добавлено общее правило SOLUTION_STEPS_RULE в системные сообщения обычного решения,
дополнений и политики библиотеки, в том числе при пользовательском системном промпте.
В steps запрашиваются разбор данных, объяснение метода, формулы, вычисления,
проверка и вывод. В problem/answer/steps запрещён служебный рассказ о поиске,
чтении библиотеки, tools, HTTP/API/JSON, повторах и внутренних рассуждениях.
При задаче о программировании/API её предметные этапы остаются допустимыми;
запрошенное учебное оформление сохраняется. Отчёт агента и снимки источников
по-прежнему отдельны от учебных шагов.

Это правило генерации, а не удаление по заголовкам или ключевым словам. Старые
сохранённые решения не переписываются. Тесты проверяют фактические исходящие
системные сообщения и протокол; новые ответы реального API по этому правилу
в текущем этапе не запрашивались.
