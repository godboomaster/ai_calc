## Использование

В настройках включить **«Разрешить агенту поиск в библиотеке»**. По умолчанию
переключатель выключен; старые запросы продолжают работать прежним способом.
При включении модель получает две операции и может решить задачу без поиска.
Просьба «Найди похожую задачу …» требует первого вызова поиска, в том числе
при пустой библиотеке. Модель, проигнорировавшая этот вызов, получает явную ошибку.

Поиск использует существующий TaskSearch и только активную библиотеку.
Шаблоны и собственная история не становятся скрытой библиотекой агента.
Чтение ограничено найденными UUID/версиями; смена версии, отклонение/отключение
примера или исходника между поиском и чтением отклоняют запрос.

read_example передаёт текст условия, авторское решение, ответ, статус проверки,
происхождение и источники с именами/номерами страниц или блоков. Пути не передаются.
Фотографии библиотечных примеров этим инструментом не отправляются; наличие фото
явно отмечается. Для полностью фотографического примера без текста — needs_image.
Выбранный пользователем образец/оформление сохраняют прежний отдельный контракт.

В блоке ответа доступны **«Прочитанные примеры»**: неизменяемый текстовый снимок,
версия, статус проверки, имена и номера источников. Просмотр диалога не заменяет
текущее решение. Это факт чтения моделью, а не математическая проверка/гарантия
использования примера. Источники дополнений сохраняются отдельно от исходного ответа.

## Протокол, стоимость и восстановление

- До 2 раундов инструментов, 8 вызовов/раунд, 5 прочитанных версий, 4 POST всего.
- Один fallback без response_format после 400/422 входит в 4 POST; инструменты
  сохраняются. Несовместимость не скрывается отключением tools. 429/500 не повторяются.
- На последнем POST инструменты запрещены; повторные tool_calls дают ошибку,
  не пятый POST. Сохраняется общий тайм-аут 8 минут и отмена HTTP.
- Полный read до 4000 Unicode-символов, все tool results до 12000,
  текст сообщений до 100000. Это ограничения символов, не токенов.
- Крупное условие/решение не обрезается; status too_large. Сокращено только
  превью поиска до 240 символов с флагом сокращения.
- До каждого POST сохраняются счётчик, фиксированные статусы и прочитанные версии
  в RequestFiles. Сырые ответы/аргументы/заголовки не сохраняются; ключ редактируется
  в материалах tools, конечном ответе и сохраняемых снимках.
- После прерывания процесса используется прежнее interrupted/manual retry поведение;
  промежуточный отчёт не запускает сеть. Готовый результат восстанавливается локально.

## Проверки

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --offline --console=plain --max-workers=2
```

**300 JVM-тестов в 43 наборах**, 0 failures/errors. `lintDebug`: **0 ошибок,
7 предупреждений**. `assembleDebug` успешен. Проверки не используют реальный API.

Новые тесты: LibraryToolsTest, LibraryAgentLoopTest, LibraryAgentHttpTest,
LibraryAgentCheckpointTest. HTTP-проверки проходят настоящим OkHttp через локальный
ServerSocket: search/read/final, правильные tool_call_id, force search, одиночный
старый запрос, совместимость образца/оформления, 422 fallback и unsupported tools.
Дополнительно проверены неизвестные/некорректные инструменты, duplicate IDs,
пределы, 429/500, отмена, источник между search/read, checkpoint ID isolation/clear,
старая история и отдельные версии в дополнениях, отсутствие фиктивного ключа в файлах.

Тест отражения фиктивного ключа провайдером воспроизвёл утечку в результате до
защиты; после редактирования — green. Тест явной просьбы поймал Unicode-регистр
русской заглавной буквы; после флага Unicode case — green.

Независимое ревью: два важных замечания и потеря имени источника, повышенная
до важного замечания по требованию сохранения источников. Все воспроизведены
до исправления и закрыты одним проходом без повторного ревью:

- 503 с Retry-After: 0 и 307/308 могли незаметно повторить POST в OkHttp.
  Запрет redirects и одноразовое тело исключают повторы транспорта; остаётся
  один явный, учтённый JSON fallback. Тесты считают реальные POST, включая
  полный fallback/search/read/final: ровно четыре, как в отчёте.
- Ключ в имени параметра графика сохранялся: теперь JSON-поля с секретом в
  имени удаляются без переименования и коллизий. Тест проверяет сериализованный
  результат и сохранность соседних параметров.
- Имя исходника старого JSON/Markdown-импорта сохраняется в optional originName
  и показывается при отсутствии ссылок на страницы. Checkpoint/history сохраняют
  это имя, редактирование секрета покрывает его тоже.

Решения выполнения: tools-only вместо старого обязательного поиска; работа здесь
без worktree; ledger вручную из-за недоступных Bash/helpers; ServerSocket вместо
недоступного Android JVM HttpServer; Unicode case для явной русской просьбы.
Риски этих решений: отсутствие изоляции отдельным worktree, ручная полнота ledger,
ограниченная HTTP-фикстура и сохранение существующих ограничений локального поиска.
Запрет redirects требует конечный URL провайдера; удаление заражённого имени
параметра может лишить график этого параметра; optional originName расширяет
формат сохраняемого снимка. Зависимость фикстуры истории от часов устранена
явными датами; существующая сериализация default timestamp этим этапом не менялась.
Отложенных мелких замечаний ревью нет.

## Границы приёмки

Реальный `deepseek-flash` с tools и новый интерфейс на эмуляторе в этом прогоне
пока не проверялись. Прежний OCR-прогон подтверждает распознавание, но не поддержку
function calling. Новых платных POST не выполнялось; ключ установленного приложения
не читался. Средства «Компьютера» в текущем сеансе не найдены: нет skill в кеше,
доступных инструментов управления и совпадения в поиске плагинов. Проверка GUI
через ADB или другое окно не подменяла согласованный пользовательский способ.
API 26, lifecycle нескольких обменов на устройстве и качество поиска
на размеченном наборе остаются отдельной приёмкой: возможные дефекты устройства,
совместимости tools у провайдера и ранжирования этими тестами не исключены.
Принудительный RAG, embeddings и чтение библиотечных фотографий исключены
пользователем и потребуют отдельного этапа при изменении этой границы.
