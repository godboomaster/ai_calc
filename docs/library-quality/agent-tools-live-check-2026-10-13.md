## Диагностика без новой отправки

По коду запроса и [официальному контракту DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)
установлен конфликт параметров: первый запрос принудительно выбирает
search_examples через именованный tool_choice, но не задаёт thinking.
На официальном API thinking включён по умолчанию; выбор конкретного инструмента
в этом режиме запрещён и возвращает HTTP 400. Имя deepseek-flash корректно,
сама модель поддерживает инструменты. Удаление response_format при штатном
fallback не меняло конфликтующую комбинацию. Это вывод из исходного запроса и
документированного контракта: исходное тело HTTP-ошибки приложение не сохранило,
поэтому дословное сообщение сервера восстановить нельзя.

Первоначальное временное исправление (заменено поддержкой thinking ниже): только для agent tools на точном хосте api.deepseek.com выставляется
thinking.type=disabled во всех обменах. Именованный поиск, ограничение POST и
JSON fallback сохраняются. Прочие провайдеры и запросы без инструментов не
получают этот параметр. Такое решение использует режим инструментов без thinking;
поддержка thinking с передачей reasoning_content остаётся отдельным расширением.

Установлены также два дефекта диагностики приложения:

- LibraryAgentLoop заменял любой 400/422 после fallback на утверждение об

  и число POST; сообщение нейтрально описывает отклонение параметров.

## Thinking с инструментами и переключатель в настройках

По уточнённому требованию пользователя временное отключение заменено полноценным
обменом thinking + tools. На api.deepseek.com при включённом режиме используются
auto/none вместо именованного tool_choice. Для явного поиска в первом обмене
доступен только search_examples; локальная проверка не допускает финального ответа
без поиска и не запускает повтор, если модель его пропустила.

Согласно [контракту thinking](https://api-docs.deepseek.com/guides/thinking_mode/),
reasoning_content текущих инструментальных ответов целиком возвращается тому же
API при продолжении. Строка (включая пустую) или явно возвращённый null сохраняют
исходное значение. Отсутствующее/некорректное поле останавливает цикл до следующего
POST. Рассуждение учитывается в лимите контекста и никогда не обрезается,
не отображается, не записывается в отчёт, checkpoint или историю.

Сохранённые прежние ответы без reasoning_content передаются как помеченный
справочный пользовательский контекст; текущие tool turns сохраняют роль assistant.
Так продолжение истории не требует сохранения скрытых рассуждений или выдуманных
полей протокола. Изображения исходного пользовательского запроса сохраняются.

В настройках для официального DeepSeek добавлен «Режим рассуждения (DeepSeek)»,
по умолчанию включённый. Он сохраняется в DataStore и задаёт thinking.type во всех
фактических запросах DeepSeek: решение, дополнение, проверка соединения, распознавание.
При выключении используется disabled и разрешён именованный поиск. Другие хосты
не получают параметр thinking; элементов на калькуляторе не добавлено.

дефектов не нашло. Регрессии проверяют auto/none, точный replay reasoning,
