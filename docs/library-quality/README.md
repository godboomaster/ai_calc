# Проверочные примеры для библиотеки

Дата: 2026-10-12. Статус: исходный набор подготовлен; ручной поиск перенесён из task-search, полная оценка RAG ещё не выполнена.

[benchmark.json](benchmark.json) содержит 12 синтетических решённых задач и 22 сценария
запросов. Q18 разделяется на два поисковых запроса: всего 23 проверяемых запроса.
Основная тема — теория автоматического управления; электрические цепи и алгебра нужны
для проверки ложных совпадений по числам и формулам. Это стартовый набор, не доказательство
качества поиска по произвольным дисциплинам.

Примеры написаны для проекта. Пользовательское фото «Вариант 3.jpg», ключи и реальные
ответы провайдера сюда не включены. Данные не являются автоматически загружаемой библиотекой
и не меняют состояние приложения.

При подготовке проверены JSON, уникальность и ссылки ID, разметка включённых/отклонённых
примеров, ссылки документов и математические тождества эталонов. Проверка не запускала
поисковый движок, импорт, Android-приложение или внешнюю модель.

## Как читать данные

- `condition`, `solution`, `answer` — текст исходного примера; `type`, `targets`, `formula`,
  `values` — ручная эталонная разметка. Извлечение этих полей моделью проверяется отдельно.
- `verification=unverified` — исходное состояние импортированного примера в приложении.
  Оно не означает, что автор теста считает все эталонные ответы неверными.
- E12 содержит намеренно ошибочное решение; оно сохранено как исходный текст, отключено
  и отклонено пользователем в сценарии. Его нельзя выдавать за подтверждённый образец.
- `relevant` — подходящие примеры; `must_rank_first` — допустимые ID первого результата.
  Несколько ID означают альтернативы, а не обязанность вернуть их все.
- `hard_negatives` — особенно похожие, но неподходящие для данного запроса примеры.
  Одинаковые числа не дают им права попасть в окончательный передаваемый контекст.
- Q19 временно отключает E08; E12 остаётся отклонённым. Нельзя «компенсировать» отсутствие
  подходящего примера передачей ошибочного решения.
- Q20 добавляет инструкцию внутрь текста документа. Она остаётся данными и не даёт
  доступа к настройкам или произвольным инструментам. Ключи для этого теста не нужны.
- Q21 требует уточнения нечитаемого знака до окончательного математического ответа.

## Предлагаемые пороги до сравнения реализаций

Это критерии для согласования, а не уже полученные результаты.

1. Все точные совпадения, различия искомой величины, интегратора, знаков и единиц — правильный
   первый результат. Отдельно считать каждый класс; общий средний балл не скрывает провал.
2. Hit@3 не ниже 90% по запросам с непустым `relevant`: хотя бы один эталонный ID в первой
   тройке. Q18a и Q18b считаются отдельно. Q16, Q19 и Q21 не входят в этот знаменатель.
3. Q16 и Q19 дают «подходящих примеров нет». Q21 даёт уточнение, а не выдуманный знак.
4. Отключённые/отклонённые примеры и `hard_negatives` не попадают в окончательно отобранные
   материалы для решения. Внутренние кандидаты до проверки соответствия могут их содержать.
5. В новых коэффициентах ответ пересчитывается; эталонный старый ответ не копируется.
6. Все показанные ссылки разрешаются в реально переданные ID и версии; выдуманных источников нет.
7. Локальный поиск по 500 примерам: ориентир p95 <= 300 мс без сети и извлечения профиля
   моделью. Измерять на устройстве, записав модель, Android, размер индекса, тёплый/холодный запуск.
   Это целевой бюджет, а не оценка текущей производительности.

Лексический поиск, поиск с профилем задачи и поиск с embeddings сравниваются на одном наборе.
Размеченные ответы не подмешиваются в запрос и не используются для выбора алгоритмом ID.
При настройке ранжирования выделяется development-набор; до итоговой приёмки нужен отдельный
набор ранее не использованных задач. Эти 12 примеров нельзя считать независимым тестом после
подгонки весов под них. Размножение одного примера до 500 измеряет нагрузку, но не качество.

## Импорт: сценарии для подготовки файлов

Для сценариев ниже создан [файловый набор](fixtures/manifest.json): TXT UTF-8/Windows-1251,
PDF с продолжением и шестью страницами, растровый PDF, DOCX с OMML и таблицей, наклонённое
изображение и нечитаемый знак, защищённый PDF и старый DOC. Все данные синтетические.
Генератор — `scripts/library_fixtures.py`; I09/I10 используют повтор/сбой с теми же файлами,
а слишком большой архив создаётся потоково в тесте. Наличие фикстур не означает приёмку импорта.

Реализован файловый импорт с проверкой черновиков и оригиналами. [Приёмка импорта](import-check-2026-10-12.md)
разделяет проверенные локальные механизмы и непроверенное качество распознавания внешней моделью.
Android-проверки выполняются в отдельном пакете, API 26 пока не проверен.

| ID | Материал | Ожидаемое поведение |
|---|---|---|
| I01 | UTF-8 TXT с E01 и E02 | Две задачи; разные искомые величины, общая формула не склеивает их |
| I02 | TXT Windows-1251 с E07 | Кириллица и обе черты модуля сохранены |
| I03 | Текстовый PDF: E06 на двух страницах | Условие и продолжение таблицы принадлежат одной задаче; обе страницы доступны |
| I04 | Скан того же PDF | Тот же смысл, формулы и границы; происхождение указывает на изображение страниц |
| I05 | DOCX с E05 в OMML и таблицей E06 | Формула и таблица извлечены либо явно помечены для проверки; не исчезают молча |
| I06 | Фото E01 и E08 под наклоном | Две задачи; модель не смешивает числа; оригинал доступен |
| I07 | Размытый знак в E04 | Знак не угадывается; задача требует уточнения и не включается в поиск |
| I08 | PDF длиннее 4 страниц | Указан весь выбранный диапазон; нет незаметного ограничения первыми четырьмя страницами |
| I09 | Повтор I03 и изменённое вручную условие | Исходный SHA256 распознан; правки не перезаписаны без явного выбора |
| I10 | Обрыв между страницами/во время POST | Сохранённые части восстановлены; неизвестный исход платного запроса требует ручного повтора |
| I11 | Документ с E12 | Ошибка автора не исправляется тайно; импорт не выставляет «Проверено мной» |
| I12 | Документ с текстом-инструкцией из Q20 | Текст не меняет системные правила, адрес API или доступные инструменты |
| I13 | Запароленный PDF, старый DOC, архив превышает лимит | Понятная причина отказа; библиотека и предыдущий черновик не повреждены |
| I14 | Две задачи на одной странице и одна на следующей | Можно разделить/объединить черновики; части не теряют связь с источником |

## Как записывать результат будущего прогона

Для каждого запуска: commit, версия набора, движок и настройки, модель распознавания/профиля,
разделение development/test, ожидаемые и фактические ID, причины ошибок, задержки, число
API-вызовов и usage при наличии. Распознавание, retrieval и качество итогового решения
измеряются отдельно. Платные запросы не входят в обычные локальные тесты.

Следующий шаг — подготовить файловые фикстуры, независимый набор и измерить дальнейшие
этапы [архитектуры](../superpowers/specs/2026-10-12-library-rag-design.md). Базовый локальный
движок уже запускается в JVM-тестах; OCR, агентный цикл и итоговый ответ модели ими не проверяются.

## Проверка переноса task-search

Перед исправлением восемь регрессий поиска/ключей воспроизвели дефекты: потерю знака,
интегратора и степени, неверный приоритет модуля, числовое совпадение при отсутствующей теме,
ключи фото по позиции и склеивание разных фотографий. Отдельно воспроизведено исчезновение
дополнений из поиска для уже открытого библиотечного примера.

`TaskSearchRegressionTest` проверяет эти случаи и поиск по собственной истории; тесты
`HistoryStoreTest` и `TemplateStoreTest` проверяют независимые фотографии, общие ссылки,
сбой копирования/записи и одинаковый размер разных изображений. Тесты не читают ключи и
не вызывают API. Это регрессионная проверка переноса, а не приёмка по всем Q01–Q22.

Независимое ревью дополнительно выявило потерю контекста фото при вопросе к библиотечному
решению. `FoundSolutionFollowUpTest` проверяет JSON-запрос с фотографиями условия и решения,
отсутствие дублей, отказ при пропавшем/слишком большом вложении и прежний текстовый сценарий
для уже распознанной ИИ задачи. Проверка не отправляет эти сообщения в сеть.

Ограничения текущего поиска: нет математического доказательства эквивалентности формул,
общего разбора LaTeX, семантических векторов, выделения ролей чисел и конвертации единиц.
Фотографии входят в ключ примера, но их содержимое без текстового описания не распознаётся.
Целевой p95 для 500 задач пока не измерен на устройстве.

Итог локального прогона переноса (2026-10-12): **181 JVM-тест, 0 падений/ошибок**,
`lintDebug` — 0 ошибок и 46 предупреждений, `assembleDebug` — успешно. Независимое
ревью закрыто после исправлений. Устройство и реальный API в этом прогоне не использовались.

Пакет метаданных библиотеки (2026-10-12): **198 JVM-тестов в 29 наборах**, без падений,
ошибок и пропусков; `lintDebug` — 0 ошибок и 46 предупреждений; `assembleDebug` — успешно.
Добавлены проверки миграции, устойчивых ID и версий, сохранения старых фото, ручной проверки,
блокировки повреждённого хранилища, повторного/конфликтующего импорта, устаревшего редактора,
а также исключения примеров из поиска без обхода через исторические снимки.
Это не проверка OCR, качества RAG или скорости на 500 задачах; устройство и API не использовались.

Дополнительно выполнена [проверка UI на Android-эмуляторе](device-check-2026-10-12.md):
импорт, статусы, версии, поиск, повторный импорт и перезапуск прошли. Основное приложение
обновлено с прежней подписью без очистки данных; реальные API-запросы не выполнялись.
