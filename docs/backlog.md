# Бэклог «Калькулятора»

Обновлено: 2026-10-13. Основание: обсуждение с пользователем и проверка текущего кода.

## Текущий фокус

На актуальный `main` перенесена основа из `task-search`: локальная база по разделам,
редактор, импорт/экспорт ZIP, JSON и структурированного Markdown, ручной поиск по базе,
шаблонам и истории. В текущей ветке вход обновлён: **✦ → 9 «Библиотека»**,
вкладки **«Поиск» / «Задачи» / «Файлы»** и общий экран **«Добавить материал»**.
Открытые библиотечные решения сохраняют самостоятельные фотографии в истории; ключи
примеров учитывают содержимое, а поиск — структуру простых текстовых формул и дополнения.

Это ручной поиск и заготовка для RAG. Добавлен импорт PDF/DOCX/текста/фотографий с оригиналами,
выбором страниц/блоков, проверкой границ и полей перед публикацией. Автоматического обращения
агента к библиотеке на main пока нет. В пакете `codex/library-agent-tools` добавлены
`search_examples`/`read_example`: агент сам выбирает поиск, без обязательной подстановки
и embeddings. Подтверждён масштаб до 500 задач; скорость ещё нужно измерить.

Добавлен пакет метаданных: постоянные ID, версии текста/фото с просмотром предыдущих,
происхождение, «Проверено мной» и отключение отдельных примеров. Старые записи мигрируют
без изменения содержимого; конфликтующий повторный импорт не заменяет локальные правки.
Непроверенные примеры доступны поиску с пометкой; отклонённые и выключенные исключены.

В пакете UI от 2026-10-13 разделены «По образцу», «Оформление» и «Библиотека»;
пояснения сокращены и разбиты на карточки с раскрываемыми подробностями. Исправлены потеря
условия из заголовка задачи и молчаливое пропускание моделью части материала: пропущенные
фрагменты сохраняются для ручной проверки без дополнительных запросов. Приёмка пакета —
[отчёт](library-quality/library-ui-check-2026-10-13.md).

Текущий пакет: подключение локального поиска к инструментам агента; [проверки](library-quality/agent-tools-check-2026-10-13.md).
Импорт реализован в ветке
`codex/library-document-import`; [приёмка](library-quality/import-check-2026-10-12.md) описывает
проверки API 35 и оставшиеся API 26/реальный OCR/lifecycle ограничения. Полная приёмка ещё не закрыта.
[Архитектура](superpowers/specs/2026-10-12-library-rag-design.md),
[UI: текущее состояние и дальнейший вариант](library-ui.md),

Наличие записи не означает поручение реализовать весь бэклог. Владельцы и сроки не назначены.

## Границы и договорённости

- Название приложения — «Калькулятор»; скрытый помощник доступен через существующие действия.
- Обычный расчёт независим от ответа ИИ; поиск и импорт не перехватывают экран калькулятора.
- Сохраняются черновики, решения, место чтения, тихая готовность и существующее фоновое выполнение.
- Примеры нужны агенту для решения; ручной просмотр библиотеки служит управлению материалами.
- Проверенность загруженного решения не предполагается автоматически. Ответы ИИ из истории
  должны сохранять своё происхождение и отдельный статус проверки.
- Предлагается локальное хранение библиотеки; выбранные материалы передаются используемому API.
  Распознавание и embeddings могут требовать внешнего сервиса — этот выбор ещё не сделан.
- API-ключ не включается в файлы задач, индекс, экспорт, журнал инструментов и диагностические данные.
- Публикация релизов только из отправленной ветки `main`; подпись остаётся локальной.

## Предлагаемая последовательность

1. Подготовить файловые фикстуры, хранение оригиналов и привязку к страницам в [хранилище](#library-storage).
2. Добавить [импорт с разделением задач](#library-import) и [проверку распознавания в UI](#library-ui).
3. Проверить [качество поиска](#hybrid-search): текущий движок — исходная точка для сравнения.
4. Подключить [инструменты агента](#agent-tools) и [источники в ответах](#solution-sources).

Ручной поиск по истории уже входит в общий поиск; сохранение запроса при возврате ещё предстоит.
Отмена удаления, подготовка фото и резервные копии остаются отдельными кандидатами.
MCP отложен до потребности использовать библиотеку из других приложений.

или существующего шаблона с сохранением происхождения.

Не входит: синхронизация между устройствами, автоматическая публикация и MCP-сервер.

### Затронутые области

`data/history/HistoryStore.kt`, `data/template/TemplateStore.kt`, новый модуль библиотеки
в `app/src/main/java/com/smartcalc/app/data/`.

### Критерии приёмки

- [x] Пример и его оригинал доступны после перезапуска; изменение хранит связь с источником.
- [x] Повторный импорт распознаётся; повторная публикация идемпотентна, новый разбор сравнивается с прежним и не заменяет локальные исправления.
- [x] Загруженный материал не получает отметку «Проверено мной» автоматически; ответы ИИ остаются в истории без автоматического добавления в библиотеку.
- [x] Отключённые и удалённые записи/источники не участвуют в новых поисках; индекс обновляется после исправления.
- [ ] Добавление в библиотеку и удаление из неё не стирают исходное решение из истории или шаблон.

## Импорт и разделение материалов на решённые задачи

Type: `Issue`
Status: `partial`
Priority: `high`
Source: `conversation`
Safety impact: `medium`

**Реализованная часть (2026-10-12):** Импорт оригиналов PDF, DOCX, TXT/Markdown, JPEG/PNG;
локальный разбор структурированного текста и извлечение OMML/таблиц; распознавание через настроенный
API; журнал без автоматических повторов; проверка, merge/split/exclusion и атомарная публикация
с квитанцией; ссылки на страницы/блоки и отдельный авторский ответ. Оригиналы можно отключать
и удалять. Android API 35 проверен в отдельном пакете. API 26, качество реального OCR и полный
lifecycle камеры/фонового сервиса остаются открытыми; подробности в [отчёте](library-quality/import-check-2026-10-12.md).

### Краткое описание и цель

Подготовить PDF, фото/сканы, Word и текст к поиску, сохранив правильную связь между условием,
решением и ответом, в том числе у задач на нескольких страницах.

### Объём задачи

Входит: извлечение текста, распознавание изображений, формул и таблиц, разделение на задачи,
привязка к оригиналу, исправление распознавания и границ перед добавлением. Учитывать .docx;
поддержку старого .doc или явную конвертацию определить отдельно. Неподдерживаемые форматы
объяснять до запуска обработки.

Не входит: автоматическое исправление математических ошибок автора и признание решения эталонным.

### Затронутые области

`data/DocumentReader.kt`, `data/ImageUtils.kt`, `data/api/OpenAiClient.kt`, новый импорт библиотеки.
Зависит от [хранилища](#library-storage).

Текущий `DocumentReader` отдаёт только первые 4 страницы PDF, обрезает текст на 20 000 символов
и не извлекает формулы Word OMML. Эти ограничения нельзя незаметно перенести на импорт сборника.

### Критерии приёмки

- [ ] Есть проверочный импорт каждого согласованного формата и задачи, продолжающейся на следующей странице.
- [x] Формулы, таблицы и рисунки сохраняются либо помечаются как требующие проверки; локальные механизмы проверены, качество внешней модели отдельно не подтверждено.
- [x] Можно объединить/разделить задачи, поправить поля, исключить пример и открыть оригинал.
- [x] Большой файл не обрезается молча: применённые лимиты, диапазон страниц и необработанная часть видны.
- [x] Есть ограничения размеров и ресурсов; отсутствие нужной возможности модели объясняется до отправки.
- [x] Отмена, ошибка и повтор сохраняют готовый разбор; квитанция исключает повторную публикацию.
- [x] Для закрытия экрана и остановки процесса определено восстановление импорта без незаметного повторного API-запроса.

## Поиск по смыслу, формулам и числовым данным

Type: `Issue`
Status: `partial`
Priority: `high`
Source: `conversation`
Safety impact: `low`

**Реализованная часть (2026-10-12):** Локальный TaskSearch по словам, числам, типу, условию, решению и дополнениям; сигнал структуры простых текстовых формул и ключи с учётом фото. Исключены выключенные и отклонённые примеры; исторические библиотечные снимки не обходят этот фильтр. Осталось: семантика, роли чисел/единицы, полноценная нормализация LaTeX и математической эквивалентности, управление целыми источниками и измерение качества/скорости. Это не CAS и не embeddings-поиск.

### Краткое описание и цель

Находить как точное условие, так и задачи того же типа с другим набором чисел и подходящим методом решения.

### Объём задачи

Входит: поиск по смыслу вопроса, текстовым совпадениям, типу задачи, структуре формулы,
заданным и искомым величинам; учёт знака, единиц и роли числа. Возвращать краткий список
кандидатов с идентификаторами и источниками; отдельно получать полную задачу или её часть.
Выбор embeddings, индекса, правил ранжирования и места вычислений сделать по проверочному набору.

Не входит: поиск по интернету и гарантия правильности найденного авторского решения.

### Затронутые области

`data/search/TaskSearch.kt`, `data/search/FormulaSearch.kt`; развивать существующий модуль. Зависит от [импорта](#library-import) и
[проверочного набора](#retrieval-quality).

### Критерии приёмки

- [ ] Находится точная задача, перефразированное условие и аналог с другими коэффициентами.
- [ ] Общие числа у задач другого типа не дают им преимущество перед действительно подходящим методом.
- [ ] Разные искомые величины, знаки и единицы учитываются; неуверенное распознавание не выдаётся за точное совпадение.
- [ ] Поиск по формуле/решению возвращает и связанное условие, даже если совпадение найдено в одном фрагменте.
- [ ] Пустая выдача отличается от ошибки; отключённые источники исключены.
- [ ] Зафиксированы измеренные качество, задержка и объём контекста; пороги выбраны до приёмки реализации.

Status: `partial`

Safety impact: `medium`

**Пакет 2026-10-13:** opt-in инструменты search_examples/read_example, существующий

checkpoint и снимки прочитанных версий в истории/ответе. По подтверждению пользователя

### Краткое описание и цель

Помощник сам выбирает использование библиотеки и вызывает поиск по прямой просьбе пользователя;
может уточнить поиск и прочитать выбранные примеры перед ответом.

### Объём задачи

Входит: предлагаемые инструменты `search_examples` и `read_example` внутри приложения,
цикл вызовов инструментов и передача выбранных фрагментов через сообщения `tool`.
Первый поиск по явной просьбе «найди похожую» обеспечивается приложением; для остальных задач
модель сама выбирает использование библиотеки. Определить лимиты повторов, контекста, времени и расходов,
поведение при отсутствии поддержки инструментов, совместимость с шаблонами и форматом ответа.
Расширить журнал запроса для нескольких API-обменов и использованных версий примеров.

Не входит: MCP-сервер, дообучение модели, неограниченные циклы и автоматическое исполнение
инструкций из загруженных материалов. Материал библиотеки передаётся как данные, не как system prompt.

### Затронутые области

`data/api/OpenAiClient.kt`, `data/request/GenerationController.kt`, `RequestRunner.kt`,
`RequestFiles.kt`, `RequestJournal.kt`, `GenerationService.kt`, `SolutionViewModel.kt`.
Зависит от [поиска](#hybrid-search).

### Критерии приёмки

- [x] При включённой настройке агент может выбрать поиск; просьба «найди похожую» требует search_examples. Прочитанные снимки доступны из ответа.
- [x] Модель может прочитать найденную версию и уточнить запрос в пределах установленного бюджета.
- [x] В контекст попадают выбранные тексты, а не вся библиотека; правило пересчёта новых коэффициентов задано. Математическое качество требует отдельной приёмки.
- [x] Пустая выдача, ошибка библиотеки и несовместимость tools различаются; обычный ответ без поиска допускается.
- [ ] После «Домой» сохраняется существующая фоновая работа, а после прерывания процесса доступен ручной повтор без скрытой платной переотправки.
- [ ] Ответ или ошибка не перехватывают расчёт; отменённый запрос не публикует поздний результат.
- [x] Неизвестные имена инструментов, неверные параметры и попытки чтения чужих путей отклоняются; отражённый ключ редактируется до сохранения.
