# Единая компоновка экранов

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Согласовать формы, пояснения, действия и навигацию без изменения хранения и генерации.
**Architecture:** Общие размеры и нижняя панель действий в ui/components; существующие экраны сохраняют свою структуру и состояние.
**Tech Stack:** Kotlin, Compose Material 3.
**Spec:** Согласованный пользователем план в диалоге от 2026-10-15.

## Ограничения
- Отдельная ветка codex/ui-layout-consistency; без merge/push/release.
- API-ключ не читать; данные основного приложения не очищать.
- Отступы 16 dp, между группами 24 dp, зоны нажатия минимум 48 dp.
- Не менять скрытый режим калькулятора, не добавлять анимации.

## Проверка рисков
- Клавиатура: сохранение доступно, поля прокручиваются.
- Узкий экран и длинные названия: действия не сжимаются.
- Переход из меню подключений открывает нужный раздел.
- Сворачивание подсказок не теряет введённый текст.
- Системные отступы учитываются один раз в AppRoot.

## Задачи
- [x] Общая панель FormActions; применить в ConnectionScreen, FormatScreen, TemplateEditScreen. Сохранение вне прокручиваемого содержимого, imePadding у формы.
- [x] SettingsScreen: группировка и сворачиваемый промпт; ConnectionScreen: один выбор формата, короткие подсказки; AppRoot/CalculatorScreen: прямой вход в подключения.
- [x] Проверить основные сценарии остальных экранов: библиотека, импорт, поиск, история, решения, шаги, камера и схема. Устранить тесные строки действий и несогласованные отступы. Границы визуального покрытия перечислены в отчёте.
- [x] Сборка, unit tests, lint; открытый эмулятор, проверка экранов и IME. Зафиксировать покрытие и ограничения в отчёте; сделать коммиты.
