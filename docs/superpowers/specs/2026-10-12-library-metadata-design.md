# Метаданные примеров библиотеки

> **Историческое проектное описание, 2026-10-12.** Статус ветки и реализации ниже относится к этому этапу.
> Документ не является текущим поручением.
> Текущие статусы — в [бэклоге](../../backlog.md), назначение документов — в [карте](../../README.md).

Дата: 2026-10-12. Следующий пакет после переноса task-search; уточнён в разговоре.

## Цель и границы

Существующая библиотека получает постоянные ID примеров, версии содержимого,
происхождение, личную отметку проверки и исключение из поиска. История ответов ИИ
остаётся отдельной: автоматического переноса в библиотеку в этом пакете нет.
Загрузка не подтверждает правильность решения. «Проверено мной» ставит пользователь.

Непроверенные примеры доступны поиску с пометкой. Отклонённые и выключенные примеры
не используются как библиотечные результаты. Автоматический поиск агентом, разбор
PDF/DOCX/сканов, оригиналы файлов и страницы, семантический индекс — следующие пакеты.

## Хранение

Продолжаем атомарное JSON-хранилище без новых зависимостей. Room из общего предложения
RAG пока не вводим: этот этап не требует отдельной базы и должен сохранить текущие данные.
У `TemplateExample` появляется необязательное `library: LibraryMetadata`; шаблоны
не получают локальные статусы библиотеки. `TemplateStore` принимает `TemplateKind`.

Метаданные: schemaVersion=1, постоянный UUID, текущая версия (от 1), источник
(LEGACY/MANUAL/FILE_IMPORT и необязательное имя файла), verification
(UNVERIFIED/VERIFIED_BY_USER/REJECTED), enabled, previousVersions.
Предыдущая версия содержит номер, текст и фотографии обеих частей и статус проверки.
История версий не рекурсивная. ID сущности отличен от уже используемого хеша содержимого.

При первом чтении старой библиотеки ID и версия 1 записываются атомарно до выдачи данных.
Текст и файлы не меняются. Ошибка чтения, неизвестная схема или ошибка миграции блокирует
запись и показывается пользователю; нельзя молча заменить повреждённую библиотеку пустой.

Правка текста/фото создаёт следующую версию, сохраняя предыдущую и её фото. Изменение
названия раздела, статуса или enabled не создаёт версию содержимого. Пустое сохранение
не увеличивает версию. Проверка при правке сбрасывается, кроме случая, когда пользователь
явно подтвердил уже отредактированный текст; последующая правка снова снимает подтверждение.
Редактор передаёт ID и ожидаемую версию, конфликт версий не перезаписывается молча.
Сохранение и удаление дополнительно сравнивают весь исходный снимок раздела: это защищает
параллельно добавленные, удалённые и изменённые примеры, в том числе отсутствующие в черновике.
Удаление примера освобождает только его собственные неиспользуемые фотографии, включая архив.

## Импорт и экспорт

Импорт всегда создаёт непроверенные включённые примеры с локальными ID и источником
«Импорт файла» (имя доступно при системном выборе файла). Метаданные из чужого файла
не могут задать доверие, локальные пути или предыдущие версии.
Экспорт переносит текущее содержимое; локальная проверенность и архив версий не экспортируются.
Это указывается в интерфейсе выбора формата библиотеки.

Повторный импорт одинакового раздела с тем же ID сохраняет локальные метаданные и файлы.
Если содержимое раздела с таким ID отличается, весь импорт отклоняется с объяснением:
существующие правки не заменяются и новые разделы из того же файла частично не добавляются.
Автоматическое объединение и UI разрешения конфликтов оставлены следующему этапу.
Различающиеся разделы с одинаковым ID внутри одного импортируемого файла также являются
конфликтом; нельзя молча отбросить второй раздел.
У шаблонов сохраняется прежнее поведение замены при импорте.

## Интерфейс и поиск

В карточке примера редактора библиотеки: источник, версия, статус, выбор статуса и
переключатель «Использовать в поиске». При REJECTED рядом объясняется исключение из поиска.
Предыдущие версии открываются внутри редактора только для чтения, включая фото.
Ошибка сохранения оставляет черновик на экране. Ошибка загрузки запрещает изменение библиотеки.

В результатах библиотеки показывается статус проверки. Фильтрация выполняется при сборке
поисковых записей, а не только в UI. Старые библиотечные снимки из истории не обходят фильтр:
найденные ранее решения с источником «База» доступны в истории, но не становятся отдельными
новыми поисковыми результатами. Самостоятельные ответы ИИ и примеры шаблонов остаются
независимыми от локального флага библиотечной записи.

## Проверка

JVM: миграция и перезапуск, стабильность ID при перестановке, сохранение/сброс проверки,
версии текста и фото, сохранение старых фотографий, отказ записи и конфликт импорта,
импорт недоверенных метаданных, исключение из поиска без возврата через историю.
Общие unit tests, lintDebug и assembleDebug. Никаких реальных API-запросов или чтения ключа.
Название «Калькулятор», обычный расчёт и сохранённые решения не меняются.
