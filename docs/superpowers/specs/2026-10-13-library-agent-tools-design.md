# Инструменты библиотеки для агента

Основание: main/ba3e3eb, подтверждённые пользователем границы 2026-10-13.
Выполнение самостоятельно здесь, в codex/library-agent-tools.

## Цель и границы

Агент получает search_examples и read_example и сам выбирает, когда искать
и какие результаты читать. Явная просьба «найди похожую» принуждает первый
обмен вызвать search_examples. Обязательной предварительной подстановки,
embeddings, новой БД, MCP и улучшения качества поискового движка нет.
Это ограниченный RAG через инструменты, а не весь прежний RAG-дизайн.

Выбран цикл tools поверх существующего OpenAI-совместимого транспорта:
одна предварительная подстановка нарушила бы согласованную автономию агента;
отдельный сервер/SDK не нужен для двух локальных операций.

## Доступ к данным

LibraryTools получает актуальные разделы, SourceCatalog и ошибку чтения.
Поиск использует TaskSearch только для активной библиотеки, без истории и
шаблонов. Действуют текущие фильтры enabled/rejected/статуса источников.
search_examples принимает query (1–2000 Unicode-символов), limit (1–5,
по умолчанию 5); возвращает UUID, версию, раздел, статус проверки,
краткое условие с явным признаком сокращения и наличие фотографий.
read_example принимает только id и целую version. Читается лишь версия,
найденная в этом запросе; актуальность/доступность повторно проверяется.
Пути, команды, URL, SQL, лишние поля и произвольные ID отвергаются.

Первый пакет передаёт текст условия, авторского решения и ответа,
происхождение, имена источников и номера страниц/фрагментов. Фотографии
и исходные файлы автоматически не передаются: hasImages и imagesNotSent
явно сообщают об этом. Для чтения чисто фотографических примеров без текста
возвращается needs_image; это не полноценная мультимодальная библиотека.
Текст и ссылки сохраняются снимком версии; состояние проверки остаётся исходным.
Материалы инструмента — недоверенные данные role=tool, не system prompt.
Модель обязана пересчитывать коэффициенты новой задачи и не исполнять инструкции
из примеров. Отсутствие совпадений отличается от unavailable/stale/invalid_arguments.

## Цикл и лимиты

В настройках добавляется «Разрешить агенту поиск в библиотеке» (default false).
Пояснение сообщает о передаче прочитанных примеров выбранному API и до 4 POST
на ответ. Это не вывод поддержки tools из имени модели.
Если библиотека пуста и запрос обычный, сохраняется прежний одиночный путь.
Явная просьба найти пример при включённой настройке использует tools и в пустой
библиотеке, чтобы корректно получить no_match.

До 2 раундов tools, до 8 вызовов в раунде, до 5 уникальных прочитанных примеров,
до 4 POST всего, включая один fallback без response_format после 400/422.
После последнего допустимого раунда или на последнем POST tool_choice=none;
повторные tool_calls завершаются ошибкой, пятого POST нет.
Никаких автоматических повторов сетевых/HTTP ошибок или отключения tools.
Сохраняется общий тайм-аут RequestRunner 8 минут и отмена HTTP.

Полный результат read_example до 4000 Unicode-символов, все результаты tools
до 12000 суммарно, текст всех сообщений до 100000; это не оценка токенов.
Полное условие/решение не обрезаются: превышение даёт too_large/context_limit.
Превью поиска до 240 символов допускает сокращение с флагом.
Отсутствие поддержки tools даёт понятную ошибку и возможность выключить настройку,
без скрытого перехода к принудительной подстановке.

## Сохранение и UI

LibraryAgentReport содержит число POST, фиксированные имена/статусы операций
и фактически прочитанные снимки. Перед каждым POST счётчик пишется в RequestFiles;
сырой ответ, аргументы инструмента, ключ и заголовки там не сохраняются.
Промежуточный отчёт не разрешает автоматическую сетевую переотправку после restart.
RequestRunner сохраняет существующий interrupted/manual retry контракт.
Готовый отчёт хранится в Solution/FollowUp с default null для старых записей.
Сохранённый конечный результат по-прежнему восстанавливается без сети.

На странице ответа показаны «Прочитанные примеры»; открытие диалога показывает
неизменяемый текстовый снимок, версию, статус проверки и ссылки-описания источников,
не заменяя текущее решение. Это факт чтения, не заявление о правильности примера.
Элемент встраивается внутрь блока ответа, не меняя индексы чтения LazyColumn.
Ошибку библиотеки и пустую выдачу UI различает. Шаблон, формат, графики и дополнения
сохраняют текущий контракт. Секрет настроек редактируется в сохраняемых снимках.

## Приёмка

JVM: фильтры и чужие ID, смена версии/отключение между search/read, строгие
аргументы, Unicode-бюджеты, no_match/unavailable, чисто фотографический пример;
search→read→final с правильными tool_call_id, независимое решение без поиска,
принудительный первый search для «найди похожую», все пределы и malformed calls;
400/422 fallback входит в 4 POST, 429/500 не повторяются, отмена не продолжает цикл;
checkpoint/история совместимы с прежними данными и не содержат ключа.
Транспорт проверяется локальным HTTP-сервером без реальных API.
Полный JVM-прогон, lintDebug, assembleDebug; GUI/реальные API — отдельная приёмка.
