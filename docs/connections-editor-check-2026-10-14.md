## Изменение

Черновик принадлежит `ConnectionEditorViewModel` конкретной записи навигации.
Исходное подключение загружается один раз. Обновление списка и смена активного
подключения не перезаписывают поля. Новая запись навигации получает отдельную
ViewModel; при закрытии редактора ссылка на ключ очищается.

Все поля, включая ключ, хранятся только в памяти до явного сохранения/копирования.
Нет SavedStateHandle, сериализации черновика или rememberSaveable для ключа.
«Проверить соединение» использует текущий черновик и больше не сохраняет его:
регрессия с закрытым локальным портом воспроизвела прежнее неявное сохранение
ключа и прошла после удаления автосохранения. Операции редактора исполняются
на главном потоке, включая навигацию после копирования и удаления.

## Сценарии

Четыре модульных теста `ConnectionEditorViewModelTest`:

- Загрузка исходных полей один раз; обновление списка не заменяет черновик.
- Повторное получение ViewModel из того же ViewModelStore сохраняет поля;
  разные записи имеют независимые черновики.
- Удаление записи навигации очищает ключ; новое открытие читает сохранённые поля.
- ID нового черновика стабилен; нормализация применяется к сохраняемой копии.

Два теста `ConnectionEditorDeviceTest` на `emulator-5554`, Android 15 / API 35:

- Существующее синтетическое подключение: изменить название, URL, ключ, модель,
  переключатели фото и рассуждения; пересоздать Activity при поворотах в landscape
  и обратно; изменить список и активное подключение; проверить поля, сохранение,
  копирование, активацию копии, удаление активной копии и независимый редактор B.
- Новое подключение: ввести черновик, проверить отсутствие ключа в marshalled
  saved instance state Activity, выполнить оба поворота, проверить отсутствие
  записи ключа при проверке соединения, сохранить и проверить активацию;
  следующее открытие нового редактора содержит пустые поля.

Команда эмулятора:

```powershell
.\gradlew.bat -PconnectionsDeviceCheck '-Pandroid.testInstrumentationRunnerArguments.class=com.smartcalc.app.ui.settings.ConnectionEditorDeviceTest' connectedDebugAndroidTest
```

До запуска Activity внешний JUnit rule проверяет тестовый package ID:
без специального флага тест отказывается открывать пользовательское приложение.
Тесты используют отдельный пакет `com.smartcalc.app.connectionscheck`, не
основное приложение и не ранее существовавший пакет проверки импорта.
Сравнения ключей выполняются без печати значений; ошибки UI-тестов очищают
фиктивные ключи из диагностического текста. Проверка файлов отчётов не нашла
фиктивных ключей.

## Проверки и ограничения

- Исходная ветка: 348 модульных тестов.
- Итог: 358 модульных тестов (6 новых для попыток и 4 для редактора), 0 ошибок.
- Эмулятор: 2 теста, 0 ошибок; настоящие пересоздания Activity при каждом повороте.
- `assembleDebug` и `lintDebug` выполнены успешно. Последний lint-прогон:
  0 ошибок, 52 предупреждения (в основном рекомендации по версиям зависимостей).
- В первом совмещённом прогоне тестов и lint старый
  `activeTimeBudgetAlsoInterruptsAnUnfinishedPost` исчерпал двухсекундный бюджет
  до POST. Отдельный запуск этого теста и затем полный модульный прогон прошли.
  Код/лимиты импорта не менялись; нагрузку lint и тестов в итоговых прогонах разделили.
- В обычном приложении Activity закреплена в portrait. Тесты принудительно
  задают ориентацию через Activity API; рабочий manifest не изменён.
- Восстановление несохранённого ключа после смерти процесса не выполняется,
  как предусмотрено заданием. На других версиях Android поворот не проверялся.
- Реальные провайдеры не вызывались: тесты попыток используют локальные серверы,
  проверка соединения в UI — закрытый локальный порт, все ключи фиктивные.

## Ручная проверка 15 октября 2026

Эмулятор SmartCalc_API35 запущен заново. Через плагин «Компьютер» вручную
открыт отдельный пакет `com.smartcalc.app.connectionscheck`; данные основного
приложения не использовались.

- В редакторе вручную введены синтетические название, локальный URL, ключ и
  модель A. Явное сохранение показало «Сохранено».
- Копирование открыло отдельный редактор копии; после изменения названия и
  модели на B и сохранения список содержит независимые A и B.
- Вручную отправлена текстовая задача через A. Локальный сервер получил
  модель A и вернул HTTP 503. После выбора B и нажатия «Повторить запрос»
  сервер получил модель B и вернул HTTP 200; на экране появился ответ «4».
  Сервер сохранял только модель, статус и результат проверки фиктивной
  авторизации, без заголовков и значений ключей.
- При активном B отдельно открыт редактор A. Название и фиктивный ключ
  изменены без сохранения. Кнопками эмулятора выполнены landscape и portrait:
  поля и скрытый ключ сохранились, модель A не заменилась моделью B.
  В landscape редактор занимает всю доступную ширину, поля доступны прокруткой.

Для настоящего пересоздания Activity временный instrumentation-помощник
разрешал поворот только текущей Activity тестового пакета и поддерживал
отрисовку Compose; поля и переходы вводились вручную через «Компьютер».
Рабочий manifest и производственный код для этой проверки не менялись.
Временный помощник и диагностические вставки удалены из исходников до переноса.
Удаление подключения проверено отдельным воспроизводимым тестом эмулятора;
в этом дополнительном ручном прогоне удаление не повторялось.
