# Выпуск APK через GitHub Releases

APK прикрепляется к релизу и не коммитится в Git. Обычный push ветки или pull request запускает
`Check Android`: тесты, lint и debug-сборку без доступа к ключу подписи.
Push тега `vMAJOR.MINOR.PATCH` запускает `Release Android`: проверки, подписанную release-сборку,
проверку сертификата, загрузку APK и SHA256 в черновик релиза, затем его публикацию.
При ошибке проверки релиз не публикуется. Незавершённую загрузку в черновик можно повторить
через **Actions → Release Android → Re-run jobs**. Опубликованный релиз не перезаписывается:
исправления выпускаются с новым номером.
Gradle Wrapper закреплён на версии 8.14 с проверкой SHA256 официального дистрибутива —
той же версии, на которой проверяется локальная сборка.

## Подпись — один раз

В **Settings → Secrets and variables → Actions → Repository secrets** нужны:

| Secret | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Файл существующего keystore, закодированный в Base64 |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль keystore |
| `ANDROID_KEY_ALIAS` | Alias существующего ключа подписи |
| `ANDROID_KEY_PASSWORD` | Пароль ключа |

Используйте именно ключ, которым подписан установленный «Калькулятор». Отпечаток его публичного
сертификата записан в `release-signing.sha256`. Workflow останавливается при другой подписи,
поскольку такой APK нельзя установить обычным обновлением с сохранением данных.
Файл отпечатка не является закрытым ключом. API-ключ провайдера ИИ для сборки не нужен.

Текущие тестовые установки подписаны локальным Android debug-ключом. Для сохранения совместимости
первые release-сборки используют тот же сертификат, но собираются с `debuggable=false`.
Не генерируйте новый debug.keystore при каждом выпуске и храните резервную копию существующего
keystore вне Git. Переход на отдельный новый сертификат требует отдельного плана миграции.

## Выпуск версии

1. Влейте проверенные изменения в ветку, из которой выпускаете релиз.
2. Укажите новую версию в `gradle.properties` (`appVersion=1.1.0`) и закоммитьте её.
3. Отправьте ветку, затем тег на конкретный проверенный коммит:

   ```bash
   git push origin HEAD
   git tag -a v1.1.0 -m "Калькулятор 1.1.0"
   git push origin v1.1.0
   ```

4. Дождитесь успешного `Release Android`. В релизе появятся `Calculator.apk`,
   `Calculator.apk.sha256` и автоматически сформированное описание изменений.

В release workflow версия берётся из тега и передаётся Gradle как `-PappVersion=1.1.0`.
В локальной сборке используется `appVersion` из `gradle.properties`.
`versionCode = major × 1 000 000 + minor × 1 000 + patch` (для 1.1.0 — 1001000).
Допустимы major 0–2099, minor и patch 0–999; 0.0.0, ведущие нули и prerelease-суффиксы запрещены.
Каждый следующий релиз должен иметь большую версию; повтор того же тега не меняет versionCode.
Package ID остаётся `com.smartcalc.app`, название — «Калькулятор».

## Проверка локально

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Для подписанной release-сборки задайте переменные окружения `ANDROID_KEYSTORE_PATH` (абсолютный
путь к существующему keystore), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
Затем выполните `./gradlew :app:assembleRelease`. Не записывайте пароли в командную строку,
отслеживаемые файлы или вывод CI. Без переменных подписи локальная release-сборка будет неподписанной.

Старые APK остаются в прежних коммитах. Их удаление из текущего дерева не переписывает историю.
