# Локальный выпуск APK в GitHub Releases

Одна команда собирает, проверяет и подписывает APK на вашем компьютере, затем загружает
`Calculator.apk` и `Calculator.apk.sha256` в GitHub Releases. Закрытый ключ и пароли
не передаются в GitHub. APK не коммитится в Git.

На GitHub работает только `Check Android`: тесты приложения и команды выпуска, lint,
debug-сборка при push ветки, тега или pull request. Workflow имеет `contents: read`,
не использует Secrets и не публикует релизы.

## Настройка один раз

Нужны Python 3.10+, Git, авторизованный GitHub CLI (`gh auth login`), JDK 17+ и Android SDK
с `platforms;android-35` и `build-tools;35.0.0`. Android Studio не требуется.
Git должен иметь доступ на запись в `origin`, а GitHub CLI — в тот же репозиторий.
Административные права в репозитории и настройка GitHub Secrets не нужны.

Скопируйте `release.local.json.example` в `release.local.json` и укажите абсолютные пути
к JDK, SDK, существующему keystore, каталогу кеша Gradle и alias ключа. Этот локальный файл
исключён из Git; он содержит только пути и alias, без паролей. `gradle_user_home` необязателен.
Gradle Wrapper закреплён на версии 8.14 с проверкой SHA256 официального дистрибутива.

Используйте тот же ключ, которым подписан установленный «Калькулятор». Его публичный
отпечаток записан в `release-signing.sha256`; команда откажется загружать APK с другим
сертификатом, именем пакета, названием, версией или включённым режимом отладки.
Отпечаток не является закрытым ключом. API-ключ провайдера ИИ для выпуска не нужен.

Текущие тестовые установки подписаны локальным Android debug-ключом. Для совместимости
обновления используют этот же сертификат, но APK собирается с `debuggable=false`.
Сохраните резервную копию существующего keystore вне Git. Замена сертификата требует
отдельного плана миграции, иначе обычное обновление с сохранением данных не установится.

## Одна команда для выпуска

Влейте проверенные изменения в `main` и отправьте их в `origin/main`.
Из ветки `main`, в корне проекта, выполните:

```powershell
python scripts/release.py 1.1.0
```

Публикация разрешена только из `main`, когда `HEAD` совпадает с актуальным `origin/main`.
Команда проверяет это до сборки, перед отправкой тега и перед публикацией релиза.
Из другой ветки, detached HEAD или неопубликованного коммита выпуск остановится.
Выбирайте ещё не опубликованную версию. Пароли keystore и ключа запрашиваются скрыто;
пустой пароль ключа означает «тот же, что у keystore». Не записывайте пароли в команду
или JSON. Для локальной автоматизации можно заранее задать процессу переменные
`ANDROID_KEYSTORE_PASSWORD` и `ANDROID_KEY_PASSWORD` через свой менеджер секретов.

Команда выполняет следующие действия:

1. Проверяет ветку `main`, её совпадение с `origin/main`, чистоту отслеживаемых файлов,
   права GitHub CLI, отсутствие опубликованного
   релиза, понижения версии и конфликта тега. Репозиторий берётся из `origin`.
2. Собирает временную копию файлов из конкретного коммита `HEAD`. Неотслеживаемые фото,
   локальная конфигурация и keystore в неё не попадают.
3. Запускает Android unit-тесты, `lintRelease` и сборку неподписанного release APK.
4. Локально подписывает APK через Android SDK `apksigner`, проверяет подпись и метаданные,
   формирует SHA256.
5. Отправляет тег `v1.1.0` на этот коммит, создаёт черновик релиза, загружает только APK
   и контрольную сумму, затем публикует релиз. Ветка автоматически не отправляется.

Результат сохраняется в `build/releases/v1.1.0/`. Если загрузка прервалась, повторите
ту же команду на том же коммите: она продолжит работу со своим черновиком. Созданные вручную
черновики не изменяются; для повторного запуска сохраняйте служебную метку в описании.
Опубликованный релиз
не перезаписывается — для исправлений нужна новая версия. Не запускайте два выпуска
одной версии одновременно.

Версия передаётся Gradle как `-PappVersion=1.1.0`; менять `gradle.properties` для каждого
выпуска необязательно. `versionCode = major × 1 000 000 + minor × 1 000 + patch`
(для 1.1.0 — 1001000). Допустимы major 0–2099, minor и patch 0–999; 0.0.0,
ведущие нули и prerelease-суффиксы запрещены. Следующий релиз должен иметь большую версию.
Package ID остаётся `com.smartcalc.app`, название — «Калькулятор».

## Проверка без публикации

```powershell
python scripts/release.py 1.1.0 --build-only
```

Этот режим проверяет, собирает и подписывает текущие локальные файлы, включая изменения
до коммита, из любой ветки. Он не обращается к GitHub, не создаёт теги и не загружает файлы. При наличии
кеша Gradle добавьте `--offline`; первый запуск Wrapper всё равно требует установленного
или загруженного дистрибутива. Обычный `./gradlew :app:assembleRelease` создаёт неподписанный APK.

Пароли передаются только процессу `apksigner`, через его окружение, без аргументов с паролями.
Gradle не получает переменные подписи и токены GitHub, а GitHub CLI не получает переменные
подписи. Это разделение не является песочницей: перед локальной сборкой чужих изменений
проверяйте код сборки, поскольку он выполняется с доступом вашего пользователя к файлам.

Старые APK остаются в прежних коммитах. Удаление из текущего дерева не переписывает историю.
